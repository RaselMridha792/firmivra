### Reports (step 7)

1. **One reporting layer.** KPI cards, detail views, the builder's preview, exports and schedules all run a report definition through `POST /business/reports/run` (an export is the same request in a format), so numbers reconcile. Quick reports are system definitions in code (`ReportSystemKey`); saved reports are `report_definitions`.
2. **Definitions, not results.** A saved report keeps the data source, ordered columns, filters (AND or OR, one level of inner groups), grouping, sort, a rolling or fixed date rule and display settings. A run keeps the definition it ran with (`report_runs.definition_snapshot`).
3. **Data sources and fields are data** (`GET /reports/sources`), filtered to what the caller may see; the builder does not hard-code them. The API checks every field, operator and grouping against it (400 `INVALID_DEFINITION`, 403 `FIELD_NOT_ALLOWED`). The database also refuses columns that name a secret.
4. **Date presets** are the dropdown's nine (`today` to `last_year`); `DB ReportDefinition.datePreset` is a free string, so the API maps them. A recurring schedule is always rolling. Custom range is a fixed spec.
5. **Comparison** is `PREVIOUS_PERIOD` or `SAME_PERIOD_LAST_YEAR`; where a source or range cannot be compared the API turns it off and says why in `notices`.
6. **Money** is in cents; "Total Revenue" follows the firm's `RevenueBasis` (COLLECTED or INVOICED) from `report_settings`, labelled on the KPI (`definition`).
7. **Exports** are runs (`kind EXPORT`): `POST /reports/exports` answers a run, `GET /reports/runs/:id` its status, `GET /reports/runs/:id/download` a 5-minute link (the documents' `DownloadLink`). Large exports are queued; export needs the Export capability (403 `EXPORT_NOT_ALLOWED`) and exports of financial or client data are audited (`report_runs.sensitive`). Print is the browser's.
8. **Schedules** run server-side in the firm's time zone; recipients are firm members or approved outside addresses and must be allowed to see the data (409 `RECIPIENT_NOT_ALLOWED`). Save & Schedule is one request (`target.kind NEW`), so nothing is scheduled when saving fails. Delete Schedule stops future runs and keeps history.
9. **Roles.** Everyone with the REPORTS view runs reports; Team Productivity and money reports are further gated (`allowed` on the category card). Saving, scheduling and exporting need Create, Edit or Manage; only a report's owner, an Owner or an Admin changes a saved report or schedule.
10. **Insights** are deterministic sentences from the numbers, each with the metric, the threshold, the period and the report or module list it opens; none is shown when data is missing or stale.
11. **No mock** yet: the client is real-API only in `apps/web/src/lib/api.ts`. A mock is a frontend task.

### API notes (step 7b)

12. **Six data sources** are built (`apps/api/src/reports/sources.ts`): clients, invoices (`invoices_payments`), payments (`payments_received`), leads, tax returns (over the filed date) and tasks. Each declares its fields (type, groupable, sortable, filterable, aggregatable, locked, sensitive) and loads the firm's rows; the engine (`engine.ts`) filters, groups, totals, charts and compares the same rows, so cards, chart, breakdown and table reconcile. Bookkeeping, Payroll, Communications and Advisory have no source yet (their dashboard cards are left out). A report loads at most 20,000 rows: past that the caller narrows the range (400 `INVALID_RANGE`). Totals are computed in memory over the loaded rows, not by SQL aggregates: fine at this size, to be revisited for big firms.
13. **Reach and restriction.** Owner and Admin see everything. Staff (and grid roles) load only the clients assigned to them; money (invoices, payments) and team data (tasks) are for Owner, Admin and a grid role with Manage on Reports; sensitive fields (email, phone) too. A restricted source or field is 403 `FIELD_NOT_ALLOWED`. A record in a quick filter (client, service, category, person) that is not the firm's, or a client Staff does not reach, is 404.
14. **Database shape changes how a definition is stored**: field names are lower_snake (the check pattern), filters are a one-item array of the contract's group, a built-in report's key uses underscores (`revenue_summary`), and a pie chart is stored as a donut. A run is recorded in `report_runs` only for a saved or built-in report (the table needs one of them), so a preview or an unsaved definition has no `runId` and no Recent Reports row.
15. **Money**: "Total Revenue" follows `report_settings.revenue_basis`: COLLECTED sums successful payments by paid date; INVOICED has no dashboard card yet (it reads null; Outstanding Invoices has the amounts). Invoice totals exclude tax unless the toggle or the firm default says otherwise, applied to the table, KPIs and chart alike.
16. **Exports are CSV only** (400 for PDF and Excel until built): quoted cells, money in dollars, a totals row, a byte order mark, text that starts like a formula made inert. The file goes to `tenant/<business>/reports/<id>.csv` through `REPORT_FILES` and is reached by a 5-minute link after the caller is checked; an export is `sensitive` and audited (ids, counts, never data). **Needs from others (infra, Rasel):** the API task role needs `s3:PutObject` on `tenant/*/reports/*` of the documents bucket (it has Get and Delete for documents) and the bucket's default encryption already applies.
17. **Schedules** store their rule and compute `next_run_at` in the firm's zone (daylight saving handled). **There is no scheduler job yet**: nothing runs a schedule on its own, and nothing is emailed or notified. Run Now makes the file for the caller. Recipients are firm members who may see the data; an outside address is refused (409 `RECIPIENT_NOT_ALLOWED`: there is no approved-recipient list); only CSV is accepted.
18. **Quick filters**: Client Type works where a source has the status values; the service, service category and staff filters are validated (the record must be the firm's) but do not narrow a source yet and say so in `notices`. Insights are two deterministic ones on the dashboard (open invoices past due, leads waiting over 2 days) and a change-against-comparison one on a run.
19. **Isolation suite**: the positive-control test has a 180 s limit (as in the Templates and Integrations PRs). The cases are in `cases/report-builder.ts` (the file `cases/reports.ts` is the older engagement reports').
