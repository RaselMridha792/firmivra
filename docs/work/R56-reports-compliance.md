## For Review 2: behaviour that changed

- #1269 (CD-F13): the API refuses a rule's `excludeStatuses` that are not real client statuses (NEW, PENDING_DOCUMENTS, IN_PROGRESS, ACTIVE, ON_HOLD, INACTIVE), on create and on edit. Rules saved earlier with free text still read as before.
- #1269 (CD-F13): Setup Recurring Deadline's "Exclude clients marked as tax-exempt" used to send "Tax-exempt" as a client status, which matched no client. It is now the criterion `notTaxExempt`, so the rule says staff must check it (no client field records tax-exempt).
- #1274 (CD-Y13), observed and kept: Staff may pause and resume a recurring definition and generate, confirm and dismiss suggestions; ending or archiving a definition, the library, rules, settings and Save as Template are Owner and Admin only. The matrix test pins this; no role changed.
- #1279 (RP-F21): report money says its basis. Invoice fields read Invoiced Subtotal, Invoiced Tax and Invoiced Total; payment fields read Amount Collected and Tips Collected. KPIs carry the basis as their definition and are never "Total Total". Column headers in CSV, XLSX and PDF exports change with them. These are the review's defaults (Revenue Summary is collected, invoice reports are invoiced) until Octavia confirms (RP-Y04).
- #1289 (CD-F14): a rule's entity types are codes from one list of federal tax classifications (Individual, Sole proprietor, single-member, multi-member, S-electing and C-electing LLC, Partnership, S and C corporation, Nonprofit, Trust or estate); the API refuses anything else on create and edit. Older rules with free text still read. A client is matched by how it is taxed: an LLC electing S counts for an S corporation rule. A client whose entity type is a bare "LLC" (when some LLC could fit the rule) or text that is no classification now goes to review with the reason, where before free text matched by spelling or not at all; an empty entity type already went to review. A client that definitely does not match is still ruled out first.
- RP-Y05 (Rasel approved, Nov 7): `POST /reports/run` needs Reports View in the permission grid, not Create. A Manager (Reports View and Export) used to export a report but get 403 opening it, and a Tax Preparer (Reports View) could not open one; both now open reports within their own reach (their assigned clients, no money or team data). No other route, role or grid default changed. Kept as observed: a Manager cannot favourite (the grid reads it as Edit and Delete).
- RP-Y03: on a report, a quick filter its data cannot use is disabled with the reason under the filters: Client Type where the source has no client status, Compare To and Date Range where it has no date, and Service Type on every report (the API never applied it, it only noted so after the run). Client Type offers only the statuses the source has.
- RP-Y16: the library's Archive asks first, then offers Undo. RP-Y09: Print prints a print copy (title, range and zone, comparison, filters, search, time, KPIs, every row up to 1,000) instead of the screen; the browser's own print prints the page's rows and says so.
- CD-Y09: a reopened deadline shows "Earlier not applicable because" with the reason it was set aside (the API always kept it; the mock now does too, and keeps the filing record).
- CD-Y07: a Government or Imported deadline with no calendar behind it says Needs Verification (no source, effective year or verified date on file); a calendar never verified reads Needs Verification, not "Not verified".
- CD-Y03, Y10: Compliance Settings lists where the other defaults are set (time zone, weekends and holidays, applicability, calendars); its At Risk hint now names Waiting on Client too, as the formula always did. The At Risk card has a Help icon with the formula and its edges.
- RP-Y12: a report compared with a period that has none of its measure says so (`comparison_has_nothing`) instead of showing no insight. The thresholds are one list in `apps/api/src/reports/metric-definitions.ts`.
